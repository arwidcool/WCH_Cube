analogClaim() (app/engine/constraints.js:255) has neither the list nor the fallback, and the
generated C configures PA4, PB0, PB1 and PC4 as GPIO_Mode_AF_PP where an analog pad must be
GPIO_Mode_AIN. Evidence with the generated C: tests/evidence/round5/2026-09-12-analog-pads.md.

Add `codegen.analog_signals` for every analog pad this part has - ADC1/ADC2 IN0..15, HSADC,
OPA P/N/OUT, CMP inputs, DAC OUT1/OUT2, VREF - each traced to its DS table. The same 162
validator warnings resolve with it: 161 are "has no af:", and they split cleanly:

    UHSIF 62, SDMMC 32     DIGITAL pads. These genuinely need an af: code read off DS
                           Table 2-1-1 / the 2-2-x tables. Without it codegen emits a TODO.
    ADC1 16, ADC2 16, OPA 18, HSADC 7, SERDES 4, CMP 4, DAC 2
                           ANALOG pads. They have no AF code and never will; analog_signals is
                           what makes the warning wrong to emit. Post on the board when the
                           block lands - the "add an af:" half of that TODO text is unfollowable
                           advice for these pads, and fixing the text is AGENT-2's.
