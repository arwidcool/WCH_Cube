WHAT EACH ROW KIND WANTS
  pin ........... a DS function on a pin that nothing routes there. Route it and give a choice
                  that claims it, or alias it, or declare it absent with a source.
  routing ....... the file routes a signal to a pin the DS does not list it on. A wrong pin, a
                  wrong remap index, or a missing alias. Read the DS row; fix the file.
  periph ........ `pins: open` - extract that peripheral's pads from the cited DS table (CH32L103
                  USBPD: CC1/CC2; RTC/BKP: PC13-TAMPER-RTC and OSC32; PWR: WKUP on PA0. CH32H417
                  USBFS: DS Table 2-2-18; USBHS: 2-2-19; USBSS: 2-2-20 via SERDES; TKEY: decide
                  whether it is an ADC mode as on CH32V006 and declare or model accordingly),
                  route them, add the choices, then DELETE the `pins:` declaration.
                  `pins: none` the DS contradicts - the claim is false; model the pads.
  chapter ....... map it in chapters: to the peripheral(s), or declare why it is not one (a
                  sentence, cited). CH32L103 13 (TKEY) and 25 (EXTEN), CH32H417 has none left.
  instance ...... map it in instances:, or declare it absent with the header line. CH32L103
                  EXTEN; CH32H417 DMAMUX.
  disagreement .. the DS's pin-first and signal-first tables differ. Record it in
                  disagreements: with both citations. The file follows the pin-first table;
                  CH32H417.notes.md already records nine of these - keep that list and the
                  coverage file agreeing.
  declaration ... an entry of yours matches nothing. Delete it or fix it.
  A parse error the tool cannot repair (a torn token, a row it cannot anchor) is a
  corrections:/noise:/pin_aliases: entry in the coverage file, cited - or, if the parser itself
  is wrong, a fix in tools/coverage_lib.py with a planted break added to
  tools/coverage_selftest.py in the same commit. Both are yours.

THE RULES THAT DO NOT BEND
  - A citation is a file:line or a DS/RM table number. A family is not a citation. "Probably
    internal" is not a reason. Where two sources disagree, record both.
  - A routed signal no choice can claim is a validator ERROR; a routing-less peripheral with no
    `pins:` declaration is a validator ERROR. Do not declare `pins: none` to make a row go away;
    the tool checks the claim against the datasheet and reports a false one.
  - Never raise `open_rows:`. If the count went up, you introduced a gap; close it.
  - After any change to the parser or a datasheet: python tools/ledger.py --write, and commit
    the regenerated data/coverage/ledger/<PART>.yaml with the change.
  - Read the markdown conversion first; the PDF is the last resort and only by a script that
    prints a `PDF FALLBACK:` line (data/sources/README.md).
  - If a signal you add is claimed by a fixture under tests/fixtures/, the fixture goes stale:
    run `node tests/fixtures/make_fixtures.js`, and say so in the commit. That folder is
    AGENT-3's; regenerating a fixture your data change invalidated is the one edit there you
    may make, and only that.
