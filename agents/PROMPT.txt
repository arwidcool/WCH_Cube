This round's rule is:

    Every choice the app offers must be one the silicon can honour.

And its complement, which governs every part you extract or extend (docs/COVERAGE.md):

    Every function the datasheet puts on a pin is modelled, or declared absent with a
    file:line, or the build is red. A part is not done while the ledger has an open row.

Concretely: run `python tools/coverage.py <PART>` before you touch a part and after every
change to it; take the FIRST open row, open the cited line, model it or declare it in
data/coverage/<PART>.yaml; never patch data/mcus/*.yaml with an ad-hoc script; never report
a part as done, on the board or in PROGRESS.md, while the tool prints an open row - report
the number instead, and lower `open_rows:` in the coverage file as rows close (it may only
go down). A peripheral that routes no pin declares `pins: { none, source }` or
`pins: { open, owner, task }`; a routed signal no choice claims is a validator ERROR.

A missing feature is a gap. An offered-but-impossible choice produces a configuration that
compiles, exports, looks correct and does not work on the board — which is worse. If the
data cannot say what the silicon allows, the mechanism that lets it say so is the
deliverable, and it must not name a part.

The standing rule from round 3 is unchanged and still catches real defects: **a name nobody
compiled is a guess.** Every SPL macro, function, struct field or enum member that reaches
data/, app/engine/codegen.js or generated C must be traceable to a header under
data/sources/<PART>/Evt/ or in ~/.platformio/packages/framework-wch-noneos-sdk. Cite the
file and line. "The other CH32 parts have it" is not a citation. Precedence for anything
the software must name: EVT → RM → DS.

Read the documents themselves in a fixed order too: the **markdown conversion FIRST, the
original PDF only as a last resort** — missing, unreadable or demonstrably incomplete,
never because it is nicer to read. `data/sources/README.md` states the rule; a script that
opens a PDF prints a `PDF FALLBACK:` line saying why, recovers by script rather than by eye,
and writes the recovered cells back into the repo so nobody opens it again.

Gate every commit on:
    python build.py && node tests/run.js            (python, not python3; must be ALL GREEN)

If you changed what the generator emits, or what an MCU file claims, ALSO compile it, on a
configuration that actually assigns pins — a default configuration generates an empty
function and proves nothing:

    node tools/wchcube_cli.js --project tests/fixtures/<fixture>.wchproj --new-project <tmp>/Proj
    cd <tmp>/Proj && pio run

Say in the commit message WHICH configuration you compiled.

If you change the UI, verify it in a REAL browser — build, then open dist/index.html in
Edge or Chrome at 1280 and 1920 wide, light and dark, 100% and 125% zoom — and write
"verified in browser" in the commit message. jsdom passing is necessary, not sufficient.

Never hand-edit dist/index.html — it is generated by build.py. Never edit
data/firmware/lib/wchcube_generated/ — it is machine-written; if the output is wrong, the
generator is wrong. Never delete a data file or a test, and never lower a threshold to make
something pass.

Never ask the human anything. If a decision is needed, make it, record it on agents/BOARD.md

stop: if your own list is empty, work the "when idle" items in your agent file, then
agents/BACKLOG.md. Get board timestamps from Get-Date -AsUTC -Format yyyy-MM-ddTHH:mmZ —
never guess one. Run the test suite serially; two runs at once corrupt each other.
