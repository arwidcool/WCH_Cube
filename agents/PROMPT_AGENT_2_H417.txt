P0 - THE THREE MECHANISMS AGENT-1 IS BLOCKED ON. Post on the board the cycle each one lands.
---------------------------------------------------------------------------------------------
CH32H417 has 78 peripherals and 66 of them have no params: block, so Parameter Settings is
empty for them. AGENT-1 is writing those. Four SHAPES cannot be written at all until you ship
the mechanism, because a params: entry written against a missing mechanism emits a TODO and
turns --strict red. These are not H417 features; they are schema shapes this repo does not have.

  1. A PER-INSTANCE INIT STRUCT. codegen.init_structs maps a struct to ONE function and
     codegen.periph_handle maps a peripheral to ONE handle. LTDC needs neither: the layer
     pixel format lives in LTDC_Layer_InitTypeDef and is applied by
     LTDC_LayerInit(LTDC_Layerx, &s) once PER LAYER, with the layer handle as an argument.
     channel_params already solved the same problem one level down for TIM channels
     (app/engine/params.js:359-410) - generalise THAT, do not add a second mechanism beside it.
     The questions the shape must answer: which instances exist, which setting decides which
     are active, what handle each one passes, and what the emitted call looks like per instance.
     Document it in data/FORMAT.md in the same commit (that file is AGENT-1's - post the block
     on the board as a REQUEST, and if it is unanswered for two cycles, write it and say so).
     Acceptance: an LTDC layer pixel format params: entry generates LTDC_LayerInit per layer,
     --strict stays 0, and the generated C compiles.

  2. TWO HANDLES FOR ONE PERIPHERAL. The H417 headers define USBFSD and USBFSH as two separate
     register blocks at the OTG_FS base; codegen.periph_handle.USBFS can name only one, so USB
     params cannot be written. The same shape appeared on CH32X035 in round 4 and was parked.
     Decide the shape (a handle per MODE choice is the obvious one - the Device/Host setting
     already exists and already decides which block is initialised) and implement it.

  3. THE af: TODO IS UNFOLLOWABLE ADVICE ON AN ANALOG PAD. app/engine/codegen.js:518-520 tells
     the reader to "Add `af:` to the signal_pins entry and generate again". For an ADC, OPA,
     CMP, DAC, HSADC or SERDES pad there IS no AF code and never will be - the fix is
     codegen.analog_signals, not an af:. Make the message say which of the two the data needs,
     from what the data already knows (the peripheral's category, and whether the pin can be
     analog at all). A TODO that names the wrong fix is worse than no TODO: it sends the next
     agent to invent a number.

Also check whether const: (you landed it in 4ef8c52) covers a unit-numbered init like
OPA_CMP_Init branching on CMP_NUM - AGENT-1 needs it for H417's OPA/CMP and CH32L103's CMP1.
Answer that on the board in your first cycle; it may already be done.

P1 - CONSUME codegen.analog_signals THE CYCLE AGENT-1 LANDS IT.
---------------------------------------------------------------------------------------------
Today the app generates GPIO_Mode_AF_PP for PA4, PB0, PB1 and PC4 on this part where an analog
pad must be GPIO_Mode_AIN - wrong-but-compiling, the exact defect class this round exists to
remove. Evidence and the generated C: tests/evidence/round5/2026-09-12-analog-pads.md.

The engine side already exists: analogClaim() reads codegen.analog_signals
(app/engine/constraints.js:255-261) and falls back to "Analog-category peripheral on an
analog-capable pin". CH32H417 declares NEITHER, so the fallback returns false and
gpioEffectiveMode() takes the alternate-function branch. Your job is the three places that must
then agree, and they must agree for every part, not just this one:
    the GPIO table         an analog pad shows an analog mode and not a speed or a pull it cannot have
    the conflict engine    an analog claim and an AF claim on the same pad is an issue that says why
    codegen               GPIO_Mode_AIN, no AFR write, no af: TODO
Then take the "analog mode inferred" note at codegen.js:461 back out of the generated C for a
part that now states the list - a note telling the reader to add something they already added is
noise. Prove both halves: a part WITH the declaration, and the fallback for one without.
