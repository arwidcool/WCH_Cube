# CI had run 30 times and failed every time, and the pack said "never run"

**2026-09-12, AGENT-3, round 6 deliverable A — the first evidence file of the round, and the
reason the round has the rule it has.**

## The premise was wrong

`PROJECT.md`, `PROGRESS.md`, `HUMAN_TODO.md` item 1 and my own brief all said CI had never
executed. Read from the API rather than from the pack:

```
GET /repos/arwidcool/WCH_Cube                 HTTP 200, "private": false
GET .../actions/workflows                     2 workflows, both "active": CI (ci.yml), Release
GET .../actions/runs?per_page=50              total_count: 30
```

`ci.yml` fires `on: push: branches: ['**']`. Every push since the initial commit had a run:

```
2026-09-12T00:04:38Z 11631a9 failure    Initial commit
2026-09-12T00:34:39Z 514735c failure    More
2026-09-12T00:49:12Z d3f047c failure    AGENT-3: the line-ending fix is verified on the runner ...
2026-09-12T01:38:37Z f3a177c failure    H417: a remap value is not a signal name ...
... (22 more, every completed run "failure", the rest "cancelled" by the next push)
2026-09-12T18:45:41Z 3d10f26 failure    AGENT-3: board - the FMC 8080 dropdown ...
2026-09-12T19:07:54Z 590f543 failure    AGENT-3: round 5 closed, round 6 opened ...
```

Zero successes in 30 runs. Nobody had read one. That is not "never run"; it is worse, and the
distinction is the whole subject of the round: a gate that nobody has watched run is a guess,
and this one had been guessed green for a day.

## What the runs said, without a token

The log body needs authentication (`GET .../actions/jobs/{id}/logs` → HTTP 403). The per-job,
per-step conclusions and the check-run annotations do not. Same shape on every completed run:

```
JOB build + tests               (ubuntu-latest)   failure   step 12 "Run tests"
JOB firmware + generated project (windows-latest) failure   step 12 "Run the tests with PlatformIO available"
JOB tauri shell (linux)          (ubuntu-latest)   success
annotations: "Process completed with exit code 1."   (and nothing else)
```

Two facts fall out before any reproduction: **`pio run` and the generated-project builds
passed on windows-latest** (they are earlier steps in the same job), so the generated C
genuinely compiles on a runner; and the thing failing is **`node tests/run.js` itself, on both
operating systems**, which means at least one cause is not OS-specific and at least one may be.

## Reproduced locally, without a token

A shallow clone into a fresh directory on this (Windows) box, `npm ci`, `python build.py`,
`node tests/run.js`:

```
2 FAILED, 719 passed  (426.9s)
  x tests/build.test.js            build › dist/index.html is not stale
  x tests/codegen_compile.test.js  codegen compile gate › the checked-in fixtures still match what the engine produces
```

Both are "the committed artifact does not equal what the tree produces", and `build.py` in that
clone wrote **1202 KB** against the committed **1181 KB** — the same source, 21 KB larger.
The clone had inherited `core.autocrlf=true` (Git for Windows' system default; this repo masks
it with a local `false`, a fresh clone does not):

```
  repo  app/template.html      CRLF=0     LF-only=4559
  clone app/template.html      CRLF=4471  LF-only=0
```

A second clone with `core.autocrlf=false` and `core.longpaths=true`, into a short path:

```
checkout ok: 0 dirty files
wrote dist/index.html 1181 KB
  ok    build › dist/index.html is not stale
  ok    codegen compile gate › the checked-in fixtures still match what the engine produces
```

Byte-identical to the commit. So the Windows job's failure is the runner's git configuration,
and `ci.yml`'s own "dist/index.html is up to date" step could not see it: it runs
`git diff --quiet`, which normalises line endings before comparing. A check that cannot see
the thing it is for.

## The three causes, all in QA's files

| Job | Cause | Fix (commit `14f5a5e`) |
|---|---|---|
| firmware (windows) | GitHub's Windows image ships `core.autocrlf=true`; every LF file checks out as CRLF; `build.py` emits a CRLF dist; fixtures no longer equal `projectSerialize()` | `git config --global core.autocrlf false && core.longpaths true` **before** `actions/checkout`, both jobs |
| test (ubuntu) | `tests/lib/browser.js` probes and finds `/usr/bin/google-chrome`, then launches without `--no-sandbox`; ubuntu 24.04 restricts unprivileged user namespaces; Chrome aborts, CDP never answers; every real-browser test **fails** rather than skips, because a browser *was* found | `--no-sandbox` when `process.env.CI` is set; never on a developer machine |
| test (ubuntu) | `tests/desktop.test.js` runs `cargo test` wherever `cargo` is on PATH and skips only when it is not; ubuntu-latest has cargo; only the `desktop` job installs Tauri's webkit2gtk/gtk deps — and that job runs `cargo test` itself | on Linux, skip with the reason when `pkg-config --exists webkit2gtk-4.1` fails |

Checked and ruled out: `build.py` is deterministic (two builds, identical SHA-256) and sorts
its one glob; `firmware_native.test.js` already skips cleanly when `pio` is absent; the three
lowercase `data/sources/*/evt` paths in tests are deliberate wrong-case probes in
`source_paths.test.js` plus one citation string (corrected, `V003/evt` → `V003/Evt`).

## The change that outlives the fix

Both test steps now tee the run and, on failure, emit every `  x <file>  <test>` line, every
`LOAD FAIL` and the verdict as `::error` annotations. Annotations are public on a public
repository. The next failure names its tests to anyone, with no login — 30 runs said only
"exit code 1".

## And the first thing it caught, on the very next run

Run `34714307941` on `14f5a5e`: `build + tests` failed **one step earlier** than before, at
"dist/index.html is up to date", with the annotation reading itself:

```
[failure] dist/index.html is stale - run 'python build.py' and commit the result
```

Cause: `3853b57` (AGENT-1, "CH32H417 params 65 -> 48") changed `data/mcus/CH32H417.yaml` by
1043 lines and the two H417 fixtures, and did not rebuild `dist/index.html`. Confirmed in the
clean clone at `14f5a5e`: `build.py` there produces a dist that differs from the committed one
by 1004 lines, with no in-flight files present. The Linux runner caught it because nothing
masks line endings there; the Windows step had been blind to exactly this class until the
autocrlf fix. The dist committed with this evidence was built from HEAD in that clean clone,
not from the shared working tree — which held AGENT-2's uncommitted engine changes at the time.

## What "read green" will mean

Not the badge. The `firmware` job's log showing the compile-gate suites reporting `ok`, not a
skip; the `Coverage ledger` step printing `6 of 6` on the runner; and this file's successor
naming the run URL. Until then `PROGRESS.md` says: **30 runs, all failed, none read** — in
those words.
